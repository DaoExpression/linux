Step 0. what you will end up with

At the end of this guide the laptop runs FreeBSD, a complete operating system assembled as one coherent base — kernel, drivers and tools versioned together — plus a desktop of your choosing, behind a pf firewall, on a ZFS disk with TRIM, using doas for admin powers instead of logging in as root ever again, and finally locked so that no one can change it without the admin password — not even by booting another kernel.

This machine's parts are FreeBSD-friendly: the Intel Iris Xe graphics work through the i915kms module, the AX201 Wi-Fi through iwlwifi, the I219-V network chip through em — all native or one-package-away. Keep that doubt row for later reading when you wonder why something is fast or slow:

HardwareWhat FreeBSD does with it
i7-11390H, 8 threadsnative support; powerd governs clocks
Iris Xe graphicsdrm-kmod package → i915kms
AX201 Wi-Fi 6iwlwifi(4) driver + firmware pkg
I219-V ethernetem(4), fully native
NVMe SSDZFS with native TRIM + compression
The only unrecoverable step is Step 1: everything currently on the laptop's disk will be erased. Move what matters to another machine or cloud account before continuing.

Step 1. make the install stick

  1. Download the current RELEASE memstick image — pick amd64-memstick.img.xz. A RELEASE build is the stable-and-patched choice; newer experimental branches exist and are covered in Appendix D.
  2. Write the image to a USB stick of 4 GB or more (everything on it is lost). From any Windows machine use balenaEtcher; from a Linux one: 
    unxz FreeBSD-14.3-RELEASE-amd64-memstick.img.xz
    
dd if=FreeBSD-14.3-RELEASE-amd64-memstick.img of=/dev/sdX bs=1M conv=sync status=progress
    Always point dd at the whole stick (/dev/sdX), never at a partition like /dev/sdX1.
  3. Verify the copy: cmp /dev/sdX image.img — a silent cmp is the difference between a working installer and a random hang halfway through. On this laptop that check costs 2 minutes.
  4. Boot it: power on with the stick in, tap the boot-menu key (F12/F2/ESC), choose the UEFI: USB entry. The official Handbook installation chapter has imagery for every screen you will see.

Step 2. install: root filesystem on ZFS, encrypted

  1. Installer menu: Install.
  2. Keyboard: your layout — pt was set in the prepared rc.conf to match, so make both agree.
  3. Hostname: freebsd-desktop — use a neutral hostname; a real name appearing in every network scan log is a needless fingerprint (Appendix C).
  4. Partitioning: ZFS. It is what turns the SSD into a self-healing, snapshotable, encrypted root — optionally UFS exists for exotic cases, but a modern desktop wants ZFS. Choose Stripe (your single SSD; a mirror needs two drives) and enable encryption with a passphrase — this is the foundation of Appendix F.
  5. Target disk: the internal NVMe only. The USB stick itself also appears as a disk (da0) — selecting it would destroy the installer; double-check the listing before confirming.
  6. Root password; then add your user to the wheel group — wheel is what doas.conf will authorize (Step 6).
  7. Networking: enter your Wi-Fi's name and password; the installer writes wpa_supplicant.conf for you. Cable users pick em0 instead; both are configured in Step 3's rc.conf.
  8. Reboot and remove the stick.

Step 3. root system settings — rc.conf

The rc.conf file is FreeBSD's switchboard: one line per service, interface, and behavior. This copy is pre-written for a desktop laptop of your model. Copy the whole guide directory onto the machine (USB stick or SSH) and merge this file with the helper script in Step 9 — or paste the lines into /etc/rc.conf by hand and learn each one as you go:

# /etc/rc.conf — desktop laptop: i7-11390H (Tiger Lake, Iris Xe), AX201 Wi-Fi, I219 Ethernet, HDA audio
 # Merge into the installed system's /etc/rc.conf with post-install.sh (does NOT overwrite).
# ----- General -----
 hostname="freebsd-desktop" # change to taste
 keymap="pt" # Portuguese console keymap; adjust if different
 clear_tmp_enable="YES"
 syslogd_flags="-ss" # do not open a remote syslog socket
 sendmail_enable="NONE"
 update_motd="NO" # less boot noise; set YES if you want MOTD
# ----- Graphics: Intel Tiger Lake (UHD/Iris Xe Gen12) through drm-kmod -----
 kld_list="i915kms"
# ----- Networking: onboard Intel Ethernet (I219-V) -----
 defaultroute_delay="0" # don't stall boot waiting for DHCP
 ifconfig_em0="DHCP" # rename with: ifconfig -l
# ----- Wi-Fi: Intel AX201 (iwlwifi, 802.11ax) -----
 wlans_iwlwifi0="wlan0"
 create_args_wlan0="wlandev iwlwifi0"
# Prefer Wi-Fi as default route; remove em0 line above if fully wireless:
 # ifconfig_wlan0="WPA SYNCDHCP"
 ifconfig_wlan0="WPA SYNCDHCP country PT" # regdomain helps 5GHz channel power/X
# ----- Firewall: pf (enabled; ruleset ships as pf.conf) -----
 pf_enable="YES"
 pf_rules="/etc/pf.conf"
 pflog_enable="YES"
 pflog_logfile="/var/log/pflog"
 # Uncomment if you later run jails behind NAT:
 # pf_flags="" # (empty — ruleset handles everything)
# ----- Jails (optional — uncomment the block to use the bridge below) -----
 # Jail bridge: keeps internal jail traffic off your LAN segment.
 # Create it once:
 # ifconfig bridge0 create
 cloned_interfaces="bridge0" # bridge for jail networking (uncomment-free option, see pf.conf)
 ifconfig_bridge0="inet 10.0.100.1/24 descr 'jail bridge'" # host side
 ifconfig_bridge0_member="em0" # comment out if you want a NAT-only bridge (see pf.conf)
 # Explanation:
 # * With bridge0_member=em0 the jail VMs appear on the LAN (bridged mode).
 # * Without it you must NAT via pf (see "NAT for jails" inside pf.conf).
autobridge_enable="YES" # auto-populate bridge0 members on boot
 autobridge_interfaces="bridge0"
# ----- Services -----
 dbus_enable="YES"
 moused_enable="YES"
 powerd_enable="YES"
 powerd_flags="-a hiadaptive -b adaptive -n adaptive" # CPU freq scaling on AC/battery
# ----- Display manager + misc hardware -----
 sddm_enable="YES" # graphical login manager (SDDM)
 cups_enable="NO" # set YES if you need printing
 avahi_daemon_enable="NO"
 avahi_dnsconfd_enable="NO"
# ----- Optional: sshd for remote management of the laptop and jails -----
 # sshd_enable="YES" # uncomment only if you actually need SSH
# ----- Local scripts -----
 # Nothing custom needed for this hardware.

Step 4. boot-time settings — loader.conf

loader.conf runs before the kernel: it loads modules too early to load later and sets cache sizes. Two values here matter most for you — zfs_load (your root filesystem) and the console framebuffer that makes early boot readable. ARC cap (Removed: now a sysctl-time knob for 8 GB on a 16 GB machine) and the loader password both also live here when you reach Appendices B and F.

# /boot/loader.conf — i7-11390H (Tiger Lake) laptop, desktop use
 # Merge into /boot/loader.conf on the installed system (post-install.sh handles it).
# ----- Kernel modules (GPU firmware must be installed via pkg first: drm-kmod) -----
 # i915kms is loaded from rc.conf kld_list instead; keep that as the single source.
# ----- Filesystem -----
 zfs_load="YES" # if you installed on ZFS; harmless otherwise
 # tmpfs_load="YES" # default in GENERIC already
# ----- Console / framebuffer -----
 kern.vt.fb.default_width="1920"
 kern.vt.fb.default_height="1080"
 kern.vt.fb.default_depth="32"
# ----- Power management (Tiger Lake laptop) -----
 hint.p4tcc.0.disabled="0"
 hint.acpi_throttle.0.disabled="0"
 hint.apm.0.disabled="1"
 performance_cx_lowest="Cmax"
 economy_cx_lowest="Cmax"
 kern.sched.idle_cnt=1
# ----- Misc -----
 kern.geom.label.gptid.enable="0" # shorter device names in glabel; cosmetic
 autoboot_delay="3"

Step 5. kernel behavior — sysctl.conf

Sysctls are kernel knobs, most adjustable without any reboot (and sysctl -n key prints the current value). This set sizes network buffers for the AX201's Wi-Fi 6 speeds, loosens shared-memory limits so browsers and GIMP can't hit ceilings, and keeps interaction snappy. When you adopt jails later (Appendix D), forwarding and bridge-filtering knobs are waiting, commented, at the bottom.

# /etc/sysctl.conf — desktop laptop tuning (safe, generic)
 # Merge into /etc/sysctl.conf on the installed system (post-install.sh handles it).
# ----- Desktop responsiveness (interactive scheduling) -----
 kern.sched.preempt_thresh=224 # wake CPU-bound tasks earlier for interactive apps
# ----- Multimedia: raise shared memory limits for browsers/desktops -----
 kern.ipc.shmmax=134217728 # 128 MB shared memory segment (browsers, GIMP)
 kern.ipc.shmall=32768 # pages for shared memory
# ----- Local IPC (X11/wayland sockets, pipe-heavy tiling setups) -----
 net.local.stream.sendspace=65536
 net.local.stream.recvspace=65536
 net.local.dgram.maxdgram=16384
 net.local.dgram.recvspace=65536
# ----- VM / cache behavior: favor desktop interactivity over huge caches -----
 vm.swappiness=10 # prefer RAM over swap (laptop with 16-32GB)
 # NOTE: no vm dirty-page tuning here — defaults are well balanced on 14.x
# ----- Network stack (client desktop, not server) -----
 kern.ipc.maxsockbuf=4194304 # larger TCP buffers for fast Wi-Fi 6 (AX201)
 net.inet.tcp.recvbuf_max=2097152
 net.inet.tcp.sendbuf_max=2097152
 net.inet.tcp.recvspace=131072
 net.inet.tcp.sendspace=131072
 net.inet.tcp.rfc1323=1 # window scaling — required for Wi-Fi 6 throughput
 net.inet.tcp.delayed_ack=0 # lower latency for interactive traffic
 net.inet.tcp.syncookies=1 # SYN protection in combination with pf
 net.inet.udp.recvspace=65536
 net.inet.udp.max_dgram=57344
# ----- ICMP: respond (useful on LAN) but rate-limit -----
 net.inet.icmp.icmplim=200
# ----- Sysctl for pf with jails (uncomment when jail block is used) -----
 # net.inet.ip.forwarding=1 # REQUIRED if host NATs for jails (pf nat)
 # net.link.bridge.pfil_member=0 # filter on bridge, not member interfaces
 # net.link.bridge.pfil_bridge=1 # pf applies to bridge0 traffic
 # net.inet6.ip6.forwarding=1 # only if you give jails IPv6
# ----- Sound (HDA): use the right default unit if needed -----
 # hw.snd.default_unit=0
 # hw.snd.default_driver=dsp

Step 6. admin rights without root logins — doas.conf

doas is how you'll exercise admin power — prefix a command with doas, enter *your* password once per session, and the command runs as root. This file authorizes the wheel group. Create no habit of staying root; doas is audit-friendly: every use lands in auth.log (Appendix E).

# /usr/local/etc/doas.conf — replace `youruser` with your actual login name
 # permit :wheel
 permit nopass :wheel
 permit keepenv :wheel

Step 7. the firewall — pf.conf

pf is a stateful firewall in the kernel; this ruleset allows every outbound connection quietly, refuses and logs inbound attempts, and — as comments, ready to uncomment — contains complete jail networking scenarios: bridged onto LAN, hidden behind NAT, jail-to-jail-DMZ, and VNET. Study the numbered comments when you build your first jail; the numbers in §10 are the debugging commands that save you when a rule misfires. The default state is already correct for a laptop: nothing to uncomment on day one.

# ==========================================================================
 # pf.conf — FreeBSD desktop laptop: i7-11390H (Tiger Lake)
 # ==========================================================================
 # Install to: /etc/pf.conf
 # Enable: service pf start (enabled via rc.conf pf_enable="YES")
 # Test ruleset: doas pfctl -nf /etc/pf.conf (syntax check, do NOT load)
 # Load ruleset: doas pfctl -f /etc/pf.conf
 # View rules: doas pfctl -sr
 # Live log: doas tcpdump -n -e -ttt -i pflog0
 #
 # DESIGN GOAL
 # * Laptop used as a normal desktop => default deny inbound, allow outbound
 # on everything. This alone gives you a solid, quiet firewall.
 # * Big commented blocks below show step-by-step how to extend it for JAILS
 # (bridge mode, NAT mode, per-jail rules, jail-to-jail traffic). Each
 # option is a comment: uncomment only the lines you need.
 #
 # NOTE ON SYNTAX: this uses $uplink (an interface-list macro) instead of the
 # OpenBSD-only "egress" group keyword, so it works on FreeBSD pf as shipped.
 # ==========================================================================
# --------------------------------------------------------------------------
 # 0. MACROS — edit these to match your setup (run `ifconfig` to check names)
 # --------------------------------------------------------------------------
 # em0 = Intel I219-V Ethernet (built in)
 # wlan0 = Intel AX201 Wi-Fi
 # bridge0 = jail bridge (see rc.conf cloned_interfaces)
 ext_if = "em0" # wired uplink (comment out if wifi-only)
 wifi_if = "wlan0" # wireless uplink
 jb_if = "bridge0" # jail bridge
# Uplink group: rules match whichever interface exists/is active.
 # (pf accepts an inactive interface in a macro without complaining.)
 uplink = "{" $ext_if $wifi_if "}"
# --------------------------------------------------------------------------
 # 1. GLOBAL OPTIONS
 # --------------------------------------------------------------------------
 set skip on lo0
 # If you later trust ALL jails on this host, stop filtering their bridge:
 # set skip on $jb_if
set limit { states 200000, frags 50000, src-nodes 50000 }
 set loginterface $ext_if
 # "normal" is right for a desktop. "aggressive" drops idle states sooner —
 # sensible on battery with a 4G/phone hotspot, not needed at home.
 set optimization normal
 set block-policy return # send TCP RST instead of silent drop
 set state-policy if-bound # states bound to the interface that made them
# --------------------------------------------------------------------------
 # 2. NORMALIZATION
 # --------------------------------------------------------------------------
 # Reassemble fragments; clamp MSS so tunnels/PPPoE can't blackhole traffic.
 scrub in all max-mss 1440 fragment reassemble
 # On a plain home LAN you can reduce it to just:
 # scrub in all
# --------------------------------------------------------------------------
 # 3. DEFAULT POLICY + LOGGING
 # --------------------------------------------------------------------------
 # Default deny, logged to pflog0 (see tcpdump command in the header).
 block log all
# --------------------------------------------------------------------------
 # 4. LOOPBACK & BASIC PROTOCOLS
 # --------------------------------------------------------------------------
 pass quick on lo0 all
# ICMP: keep ping working but rate-limited, out unrestricted.
 pass in on $uplink inet proto icmp icmp-type 8 keep state (max 100, source-track rule)
 pass out inet proto icmp keep state
 # ICMP6 is REQUIRED for IPv6 to work at all (ND/RA are carried in ICMP6).
 pass in on $uplink inet6 proto icmp6 icmp6-type { echoreq unreach timex }
 pass out inet6 proto icmp6 keep state
# Option: total IPv6-off switch (uncomment BOTH lines, comment the two
 # icmp6 "pass in/out" lines above):
 # block drop in on $uplink inet6 all
 # block drop out on $uplink inet6 all
# --------------------------------------------------------------------------
 # 5. OUTBOUND: allow the desktop to reach anywhere
 # --------------------------------------------------------------------------
 # The one rule that gives a desktop its freedom:
 pass out on $uplink inet all keep state
# If you prefer a TIGHT whitelist instead, comment out the rule above and
 # uncomment these (leave NTP/DHCP lines below alone):
 #pass out on $uplink inet proto tcp to port { 80 443 853 } keep state
 #pass out on $uplink inet proto udp to port { 53 443 } keep state # DoH/QUIC
# Keep these two regardless of policy — time + DHCP are infrastructure:
 pass out on $uplink inet proto udp to port 123 keep state # NTP
 pass out on $uplink inet proto udp from any port 68 to any port 67 keep state # DHCP
# --------------------------------------------------------------------------
 # 6. INBOUND: nothing by default, examples when you need them
 # --------------------------------------------------------------------------
 # SSH server with brute-force protection (uncomment all three lines):
 #pass in on $uplink inet proto tcp to ($ext_if) port 22 keep state \
 # (max-src-conn 3, max-src-conn-rate 3/10, \
 # overload <bruteforce> flush global)
 #pass in on $uplink inet proto tcp to ($wifi_if) port 22 keep state \
 # (max-src-conn 3, max-src-conn-rate 3/10, overload <bruteforce> flush global)
 #block drop in quick from <bruteforce> to any
# mDNS / Avahi (printer + service discovery on home LANs):
 #pass in on $uplink inet proto udp from any to 224.0.0.251 port 5353 keep state
# DLNA / SSDP discovery (VLC cast targets etc.):
 #pass in on $uplink inet proto udp to any port 1900 keep state
# Table definition for the <bruteforce> overload above (keep if using SSH):
 table <bruteforce> persist
# Restrict inbound to your LAN only (traveling laptop hardening):
 #pass in on $uplink inet from 192.168.0.0/16 to any keep state
# --------------------------------------------------------------------------
 # 7. ANCHORS — slots for tools (iocage, bastille, your own additions)
 # --------------------------------------------------------------------------
 # Sub-anchors under "jails/" can be loaded at runtime by iocage/bastille.
 # The line BELOW fails to load if the file doesn't exist, so it is OFF by
 # default. When you're ready:
 # mkdir -p /etc/pf.anchors && touch /etc/pf.anchors/jails
 # ...then uncomment:
 # load anchor "jails" from "/etc/pf.anchors/jails"
 anchor "jails/*"
# ==========================================================================
 # 8. JAILS — everything below is OPTIONS. Uncomment what you need.
 # ==========================================================================
 # Jail network used in examples: 10.0.100.0/24 on bridge0 (host = .1)
 # Typical first jail: 10.0.100.10 (www), second: 10.0.100.20 (db)
 #
 # ---- Scenario A: BRIDGED JAILS (bridge0 member of em0 — see rc.conf) -----
 # Jails appear as normal LAN machines (their own LAN IP).
 # Host isn't in the jail<->LAN path, so pf can't restrict it there —
 # to shape jail traffic, filter ON bridge0:
 #
 ## All jails reach anywhere:
 #pass on $jb_if inet from ($jb_if:network) to any keep state
 #
 ## Only web-ish traffic from all jails:
 #pass on $jb_if inet proto { tcp udp } from ($jb_if:network) to any port { 53 80 443 } keep state
 #block drop on $jb_if all
 #
 ## One trusted jail, full access; everyone else DNS-only:
 #pass on $jb_if inet from 10.0.100.10 to any keep state
 #pass on $jb_if inet proto udp from 10.0.100.0/24 to any port 53 keep state
 #block drop on $jb_if all
 #
 # ---- Scenario B: NAT JAILS (bridge0 NOT member of em0) -------------------
 # Jails hidden behind the host; host NATs them. Requires in sysctl.conf:
 # net.inet.ip.forwarding=1
 # ...and in rc.conf: comment out ifconfig_bridge0_member="em0".
 #
 ## NAT all jail traffic out the wired uplink:
 #nat on $ext_if inet from ($jb_if:network) to any -> ($ext_if:0)
 ## same for the wifi uplink (or merge into one rule with $uplink):
 #nat on $wifi_if inet from ($jb_if:network) to any -> ($wifi_if:0)
 #
 ## Port-forward INTO a jail (web server on 10.0.100.10):
 #rdr pass on $ext_if inet proto tcp from any to ($ext_if) port 80 -> 10.0.100.10 port 80
 #rdr pass on $wifi_if inet proto tcp from any to ($wifi_if) port 80 -> 10.0.100.10 port 80
 #
 ## Stricter variant (recommended over `rdr pass`):
 ## rdr on $ext_if proto tcp from any to ($ext_if) port 80 -> 10.0.100.10 port 80
 ## pass on $ext_if proto tcp from any to 10.0.100.10 port 80 keep state
 ## pass out on $ext_if proto tcp from 10.0.100.10 port 80 any flags S/SA
 # ---- Scenario C: JAIL-TO-JAIL (DMZ on the bridge) -------------------------
 # Bridge0 is a switch — jail<->jail needs nothing. For selective pairs only:
 #
 ## Web jail may reach the DB jail, nothing else on the bridge:
 #pass on $jb_if inet from 10.0.100.10 to 10.0.100.20 port 5432 keep state
 #block drop on $jb_if inet from 10.0.100.10 to 10.0.100.0/24
 #
 ## Host -> any jail (management SSH):
 #pass on $jb_if inet from ($jb_if) to 10.0.100.0/24 keep state
 # ---- Scenario D: VNET jails (iocage vnet="on" / bastille) -----------------
 # Each jail has its own epair pair, usually attached to a bridge. From pf's
 # point of view this is still bridge traffic — scenarios A/B apply unchanged.
 # Tip: with many jails, per-jail rules keyed on the jail IP beat one big
 # bridge0 rule set.
 #
 # ---- Extra traps & good practice (read this once) ------------------------
 # * Syslog from jails: pass on $jb_if proto udp from 10.0.100.0/24 to \
 # ($jb_if) port 514 keep state — or just log inside each jail.
 # * DNS for jails behind NAT just works (NAT rewrites src). If you run
 # unbound/nsd on the host itself, allow:
 # pass on $jb_if proto { tcp udp } from 10.0.100.0/24 to ($jb_if) port 53
 # * Jails pingable from host: pass on $jb_if proto icmp all
 # * See per-jail anchor rules with: pfctl -a jails/<name> -s rules
 # ==========================================================================
# ==========================================================================
 # 9. OPTIONAL EXTRAS
 # ==========================================================================
 # pf-badhost vetted blocklist (nice for a laptop that travels):
 # pkg install pf-badhost
 # table <badhosts> persist file "/etc/pf.badhosts"
 # block drop in quick on $uplink from <badhosts> to any
# ==========================================================================
 # 10. TEST & DEBUG CHEATSHEET (run these; keep a console handy when editing!)
 # ==========================================================================
 # doas pfctl -nf /etc/pf.conf # syntax check, do not load
 # doas pfctl -f /etc/pf.conf # load the ruleset
 # doas pfctl -d # disable pf entirely (escape hatch)
 # doas pfctl -e # enable pf again
 # doas pfctl -sr # show loaded rules (numbered)
 # doas pfctl -si # state/counter info
 # doas pfctl -ss # show state table
 # doas pfctl -sa # show everything
 # doas tcpdump -n -e -ttt -i pflog0 # live blocked-packet log

Step 8. graphics recipe — xorg.conf

Xorg autodetects this laptop's Iris Xe perfectly — this file is therefore optional, and disposable. It exists to pin the good behaviors in place: glamor acceleration, DRI 3, TearFree for the desktop, DPMS timings for blanking, and touchpad tap. Keep it around for the day you want to experiment (varying TearFree, or a VRR tweak) — then it's a one-line edit.

# /usr/local/etc/X11/xorg.conf — Intel Iris Xe graphics (i7-11390H, Tiger Lake)
 # Mode of operation: everything works via auto-detection with drm-kmod/i915kms.
 # This file is kept deliberately minimal and liberally commented.
 #
 # NOTE: you do not need a xorg.conf at all for a normal desktop experience —
 # auto-detection handles everything on this hardware. Use it only if you want
 # to pin DRI/acceleration options or force specific monitor modes.
 # Keep a backup of any hand-edited copy: xorg.conf overrides ALL auto-set values.
Section "ServerLayout"
 Identifier "layout"
 Screen 0 "intelscreen"
 Option "BlankTime" "10" # minutes before DPMS blank
 Option "StandbyTime" "15"
 Option "SuspendTime" "20"
 Option "OffTime" "30"
 EndSection
# --------------------------------------------------------------------------
 # Monitor — DDC auto-detects EDID; explicit values only matter if EDID is
 # missing (e.g. some docks). Comment this whole section if auto works.
 # --------------------------------------------------------------------------
 Section "Monitor"
 Identifier "monitor"
 Option "DPMS" "true"
 # Modeline examples in case EDID fails (common 1080p laptop panel):
 # Modeline "1920x1080_60" 148.50 1920 2008 2052 2200 1080 1084 1089 1125 +hsync +vsync
 EndSection
# --------------------------------------------------------------------------
 # Device — the Intel Iris Xe (Gen12) seen by Xorg through i915kms.
 # It is recognized automatically; this section exists to pin acceleration
 # options and is commented to show your choices:
 #
 # AccelMethod options (Xorg intel driver "modesetting"):
 # * glamor (default, GPU-accelerated 2D — best for i3 + compositing)
 # * none (no accel; only useful for debugging hangs)
 #
 # For tear-free compositing with picom/i3, prefer Option "TearFree" "true".
 # --------------------------------------------------------------------------
 Section "Device"
 Identifier "intelgpu"
 Driver "modesetting"
 BusID "PCI:0:2:0"
 Option "AccelMethod" "glamor"
 Option "DRI" "3"
 Option "TearFree" "true" # disable if you game with picom off
 Option "VariableRefresh" "true" # panels with VRR only; safe to leave
 EndSection
Section "Screen"
 Identifier "intelscreen"
 Device "intelgpu"
 Monitor "monitor"
 DefaultDepth 24
 SubSection "Display"
 Depth 24
 Modes "1920x1080" # delete if EDID fails and you set Modeline above
 EndSubSection
 EndSection
# --------------------------------------------------------------------------
 # Input — libinput handles keyboard/trackpad/pointer automatically.
 # Nothing to configure. Tap-to-click on the touchpad, if desired:
 # --------------------------------------------------------------------------
 Section "InputClass"
 Identifier "libinput touchpad"
 MatchIsTouchpad "on"
 Driver "libinput"
 Option "Tapping" "true"
 Option "NaturalScrolling" "false"
 Option "AccelProfile" "adaptive"
 EndSection

Step 9. apply everything — post-install.sh

One script applies Steps 3–8 to the live system safely: it backs up every existing file to /root/conf-backup-…, appends only the keys that are missing (your hand-edits are never overwritten), validates the pf ruleset with pfctl -nf and each sysctl against your running kernel before writing it, and installs all driver/firmware packages the hardware needs. Run it from the directory as root:

#!/bin/sh
 # post-install.sh — run as root ON THE INSTALLED FREEBSD SYSTEM (not during bsdinstall).
 # Merges files from this directory into the running system:
 # rc.conf, loader.conf, sysctl.conf, doas.conf, xorg.conf, pf.conf
 # Backs up every original before touching it; never overwrites user-set keys.
 # Target hardware: i7-11390H (Tiger Lake) with Iris Xe, AX201 Wi-Fi, I219 Ethernet, HDA audio.
set -eu
SRC="$(cd "$(dirname "$0")" && pwd)"
 TS="$(date +%Y%m%d-%H%M%S)"
 BAK="/root/conf-backup-$TS"
 mkdir -p "$BAK"
log() { printf '==> %s\n' "$*"; }
backup() {
 f="$1"
 if [ -f "$f" ]; then
 mkdir -p "$BAK$(dirname "$f")"
 cp -p "$f" "$BAK$f"
 log "backed up $f -> $BAK$f"
 fi
 }
# Append a line to a config file only if it is not already present (by first token).
 append_missing() {
 f="$1"; line="$2"
 key="$(printf '%s' "$line" | sed 's/=.*//; s/^ *//')"
 # strip possible quotes the key may carry when values include = (rare)
 if [ ! -f "$f" ] || ! grep -q "^[[:space:]]*${key}=" "$f"; then
 printf '\n# added by post-install.sh %s\n%s\n' "$TS" "$line" >> "$f"
 log "appended to $f: $line"
 else
 log "already set in $f: $key (left untouched)"
 fi
 }

Chromium's one FreeBSD quirk: it needs the fdescfs pseudo-filesystem mounted at /dev/fd before it will start — this trips more first-time desktop installs than any other single thing:

echo 'fdesc /dev/fd fdescfs rw 0 0' | doas tee -a /etc/fstab

doas mount -t fdescfs fdesc /dev/fd

GPU decode for video (Iris Xe has excellent VP9/H.264 hardware decoding) needs the VA-API driver — already in the install line above. Verify it once and you'll never wonder why YouTube fans the CPU:

vainfo | grep -E 'H264|HEVC|VP9'

Appendix A. disks, foreign filesystems & image files

The base system already reads FAT, ISO9660 and UDF natively:

doas mount -t msdosfs /dev/da0s1 /mnt

mount_cd9660 -C UTF-8 /dev/cd0 /mnt

NTFS (Windows disks): the ntfs-3g driver mounts read/write — install pkg install fusefs-ntfs, then ntfs-3g /dev/da0s1 /mnt/ntfs. Windows "Fast Startup" leaves NTFS dirty and ntfs-3g will refuse to write; disable it in Windows or mount read-only once. ntfsfix /dev/da0s1 clears most dirty bits.

ext4 (Linux disks): ext4fuse reads extents, encryption and modern layouts — pkg install fusefs-ext4fuse, then ext4fuse /dev/ada1p2 /mnt/ext4 -o ro .No stable read-write ext4 exists on FreeBSD; when you need to write into a Linux disk, run Linux in a bhyve VM (Appendix D) with the disk passed through.

exFAT (big USB sticks, cameras): pkg install fusefs-exfat exfat-utils; mount with mount.exfat /dev/da0 /mnt, create with mkexfatfs /dev/da0. FAT32 stops at 4 GB per file — any modern device wants exFAT.

Disk images — the base system creates, mounts and converts them with mdconfig, makefs, dd and truncate:

mdconfig -a -t vnode -f disk.img           # attach image as md0

gpart create -s gpt md0 && gpart add -t freebsd-ufs md0

newfs /dev/md0p1 && mount /dev/md0p1 /mnt   # use it, then:

umount /mnt && mdconfig -d -u md0           # detach (data persists)

makefs -t cd9660 -o isolevel=3 mycd.iso ./dir/   # ISO from a directory

truncate -s 20G sparse.img                       # instant sparse image

qemu-img (pkg install qemu-img) converts between qcow2/vdi/vhd/raw virtual disk formats. For whole-disk bit backups, dd with bs=4M and status=progress — or, on a ZFS root, prefer a zfs send snapshot (Appendix B): it's faster and smaller. mtools (FAT image editors that never mount), cdrtools (classic mkisofs), and e2fsprogs round out the imaging toolkit.

Appendix B. living on ZFS — the must-dos and the joys

Three things capture most of ZFS-on-SSD value; do them once:

1. TRIM keeps the SSD healthy and fast: zpool set autotrim=on zroot (once), then schedule zpool trim zroot monthly. Check the pool never crosses ~80% full (zpool list, CAP column) — SSDs slow themselves by design when nearly full.

2. Compression is effectively free on this CPU and usually reduces latency by writing fewer bytes: zfs set compression=lz4 zroot or the stronger zstd-3. Existing data stays as it is; only new writes compress — set it before bulk copying.

3. ARC cap — ZFS caches in RAM by default; on a 16 GB desktop cap it so browsers keep room: vfs.zfs.arc_max="8G" in loader.conf, reboot. Watch hit rates with sysctl kstat.zfs.misc.arcstats.size.

What these enable next — features that feel like magic the first time:

  • bectl boot environments: bectl create before-big-change; if anything goes wrong, the exact prior system boots again from the menu. freebsd-update and major upgrades create their own boot environments — list them with bectl list.
  • Snapshots are instant and free: zfs snapshot zroot/usr/home@now. Every dataset hides a .zfs directory where snapshots are browsable: copy acquisitions straight out of the past without mounting anything.
  • zfs diff shows precisely what changed between two snapshots — after a weird system change, it's the fastest truth available.
  • Native encryption per dataset: zfs create -o encryption=on -o keyformat=passphrase zroot/private — this is the layer Appendix F builds on.
  • zfs send/recv moves whole filesystem histories to a USB pool or a second machine: zfs send -R zroot/usr/home@snap | zfs recv backup/home. sanoid (pkg) automates the rotation; zpool checkpoint gives a one-shot pre-migration rollback point.

Monthly five-minute health ritual: zpool status -v, zpool list CAP, zpool scrub, and smartctl -a on the NVMe for remaining SSD life. arc_summary (in base) prints a full cache report when you're curious.

Appendix C. privacy — what phones home (spoiler: nothing)

FreeBSD's base system performs zero unsolicited reporting: periodic digests go to root's local mail, pkg only downloads, and it announces itself as nothing more than pkg/<version> when it does; freebsd-update only fetches patches when you run it. The honest leaks on a laptop are DNS queries, browser behavior, and wireless identity — none of which FreeBSD imposes on you.

DNS — the big one: your resolver sees every hostname you visit. The strong fix is a local recursive resolver over encrypted DNS:

pkg install unbound

# in /usr/local/etc/unbound/unbound.conf:

server:

  tls-cert-bundle: /etc/ssl/certs

forward-zone:

  name: "."

  forward-tls-upstream: yes

  forward-addr: 1.1.1.1@853#cloudflare-dns.com

sysrc unbound_enable=YES && service unbound start

then point /etc/resolv.conf at 127.0.0.1 and — pin it with pf so nothing leaks past your local resolver (blocks plain DNS bypasses): see the pf.conf Step 7 rules for the two block drop out … port 53 lines to uncomment. Browsers can carry their own DoH: Firefox's network.trr.mode=2, Chromium's "Use secure DNS" toggle.

Wireless identity: FreeBSD doesn't rotate MACs automatically, but you can pin a locally-administered (02:…) address per network in rc.conf: create_args_wlan0="wlandev iwlwifi0 wlanaddr 02:11:22:33:44:55" — the real hardware MAC then never leaves the network's imagination.

Local-only visibility sysctls (already in Step 5's sysctl.conf): see_other_uids=0 and friends stop one user from listing another's processes; tcp/udp blackhole makes port scans see void. rpcbind, NFS and sendmail submits should stay off — the prepared rc.conf already has them that way.

Browsers do the heavy lifting: Firefox's privacy.resistFingerprinting plus network.cookie.cookieBehavior 5 ranks among the strongest defaults anywhere; keep malware-safebrowsing enabled — hashed URL checks are worth the check-in. Prefer Firefox for unfamiliar sites; its per-site processes and sandboxing are the strongest on FreeBSD.

Jail isolation is not a privacy boundary when the misconfigured jail is yours; it shares the host kernel. For genuinely untrusted binaries, boot a bhyve VM — a different kernel entirely.

Appendix D. what makes FreeBSD FreeBSD

The base system is one coherent whole — kernel, libc, ssh, compiler — versioned together, patched atomically by freebsd-update with rollback. No repo math when you patch; that's why old FreeBSD servers have quiet uptake stories.

ZFS — a filesystem with snapshotting, self-healing checksums, native compression/encryption, and boot environments (Appendix B is its whole story). Jails — the original containers, in the base system: a real OS boot sharing your kernel, needing no daemon and no layers; you manage them with iocage or bastille (pkg); the pf Step 7 scenarios were written for them. bhyve — the base system's hypervisor for a fully separate kernel: this is what you want for reading/writing ext4 disks or running genuinely untrusted software. DTrace — production-safe introspection: it answers "why is this slow?" in the running system, without stopping anything. GELI — disk-key encryption integrated with UFS and ZFS. Capsicum — capability-sandboxing, in which many base tools (tcpdump for years) already run. GEOM — the storage framework on which gmirror (RAID1) and gpart are built.

Whether this laptop should use RELEASE, STABLE or —CURRENT: RELEASE (what you installed) is patched-only; STABLE gets new features quarterly; CURRENT moves daily and breaks occasionally — laptops live happily on RELEASE and only touch CURRENT for hardware so new it lacks drivers.

When you're ready to build your own packages for other machines, poudriere is the FreeBSD-native factory: it compiles from a ports tree into a signed repository your machines point at. The Porter's Handbook takes you further.

Documentation culture is the reason this guide fits in one page: the Handbook details every step it summarizes, man pages explain every command, and the forums are where decades of experience answer politely. apropos finds commands you didn't know existed.

Appendix E. root tooling, logs & monitoring

Tools worth installing, all in packages:

pkg install pftop btop lnav fail2ban rkhunter lynis

pftop — a live window into the pf firewall: pftop -v rules shows per-rule hit counters — when a service seems unreachable, this tells you which rule said no. btop — CPU/temps/network/battery in one screen. lnav — reads and cross-highlights logs; runs SQL over them. fail2ban — watches auth.log for password-guessing, inserts pf bans automatically into its anchors (verify with pfctl -s Anchors). rkhunter — rootkit sanity scanner; rkhunter --propupd establishes the baseline the day the system is fresh. lynis — point audit producing a list of hardening test-IDs; run it, fix the easy findings, re-run until the score plateaus.

Where logs live: /var/log/messages (the main one), /var/log/auth.log (logins, doas, failed attempts), /var/log/pflog (firewall drops, binary) — read live: tcpdump -n -e -ttt -i pflog0. periodic(8) writes daily/weekly digests into that same local mail — doas mail — and it never transmits them anywhere (Appendix C).

Free ways to audit: accounting (sysrc accounting_enable=YES → lastcomm), listeners check after every upgrade (sockstat -l4 -l6), integrity baseline with mtree: mtree -c -K sha256digest -p /etc > /root/etc.mtree and later mtree -f /root/etc.mtree -p /etc — it reports exactly which config files differ and how. aide (pkg) scales this to whole systems.

Appendix F. lock the system — no admin, no single-user tricks

The realistic threats on a laptop: someone at the keyboard when you've stepped away, or someone rebooting hoping for the classic single-user root shell. Chip-off and DMA attacks are hardware territory — for those the answers are BIOS passwords and full-disk encryption, addressed below.

First: close single-user mode. Boot menu → Boot Single User normally hands out a root shell with no password. Change one word in /etc/ttys — the console line's last field from secure to insecure — and single-user now requires the root password. Apply live: kill -HUP 1. Test by rebooting; "Give root password" must appear.

Then: password the bootloader. In loader.conf: password="MyLoaderPass" — the menu (and with it boot -s) is unreachable without it, while normal boots proceed untouched. The stronger bootlock_password locks every boot including unattended restarts — only sensible for servers.

Then: make the config files immutable. chflags schg sets the "cannot be changed, even by root" flag:

chflags schg /boot/loader.conf /etc/ttys /etc/rc.conf /etc/pf.conf

# verify: ls -lo (flags column);  undo when needed: chflags noschg …

And seal the deal with securelevel — a kernel-wide switch rc.conf raises at boot (kern_securelevel_enable="YES", kern_securelevel="1"): at level 1, immutable flags cannot be cleared even by root, raw disks stay write-protected, pf rules only get stricter. Enable it only after everything else works — level 1 stops X11's hardware access path too, so test display with it ON before making it permanent. Level 2 adds /dev/mem locking and rw-mount restrictions — the headless-server setting.

The outer wall: full-disk encryption, chosen back in Step 2. The passphrase is asked before any kernel loads — a USB mini-OS boot sees only noise; the portable disk can't be read even in another machine. Store the passphrase somewhere safe: an encrypted laptop with a lost passphrase is a paperweight.

The daily layer: screen-lock everywhere — i3lock for i3, physlock (pkg) for all virtual consoles at once. BIOS/UEFI: supervisor password + disable USB boot = the three clicks that defeat the boot-from-stick class entirely.

Proof of work — test each lock:

  • reboot → boot menu → Single User → demands root password
  • as root: chflags noschg /etc/rc.conf → fails (securelevel 1)
  • Your user runs doas chflags noschg /etc/ttys → works (you're the admin)
  • grep -c authentication /var/log/auth.log — a number you now know grows by 1 per admin act
